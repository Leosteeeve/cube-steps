# V1 validation

Date: October 12, 2026 (America/Los_Angeles).

This record covers the initial local validation of V1. The seven LBL stages, courses, free solving, and synchronized player are implemented. Stable-release acceptance remains pending until a club member follows the lessons with a physical cube.

## Evidence

- Node.js 24.18.0; npm 11.16.0; cubing.js 0.65.1. Other exact versions are locked in package-lock.json.
- Solver corpus: xorshift32 seeds 1–1,000, 25 face turns per scramble, no consecutive identical face. Each case is replayed through the complete trace and solved again for determinism.
- Cross cases: all 24 locations/orientations for each white edge. Coverage also includes trapped corners/edges, repeated triggers, stage skips, and final-stage temporary disturbance.
- Browser targets: Playwright Chromium and WebKit on Windows; desktop 1440px and mobile viewport 390px. These are browser simulations, not physical phone tests.
- Production smoke tests exercise `/cube-steps/`, solver workers, random-scramble workers, the actual renderer's solved state, and route refreshes.
- Captured screenshots and checked controller boundaries against the actual renderer. Console/page errors and failed asset responses are checked in browser tests.

After the clean-install run, an independent whole-branch review found two important playback defects: Play retained a finished replay's endpoint, and reselecting the same stage did not seek again. Both were reproduced with failing regression tests, fixed, and verified with the complete typecheck, Vitest, build, interaction, and production suites. The final counts above include those regressions. No critical or minor findings were raised; the reviewer declined no behaviors. There was no second review pass.

Desktop and mobile screenshots were visually inspected. Physical-cube acceptance is separate and remains pending.

## Execution decision

Development used a fresh dedicated clone on `codex/lbl-v1`. The native worktree tool could not target the nested repository because the task's parent directory was not a Git repository. No previous local source was overwritten. The tradeoff is that this branch has no additional linked checkout; edits remain isolated from `main` in the dedicated clone.

## Known limits and pending acceptance

- Physical-cube follow-along by a club member: **pending**. Check white-cross alignment, trapped-piece extraction, and the final corner stage with its whole-trigger and fixed-grip instructions.
- Real mobile touch devices and assistive-technology sessions: **not yet manually tested**.
- GitHub-hosted CI: passed for [PR #1](https://github.com/Leosteeeve/cube-steps/pull/1). On October 12, the owner authorized a public club preview on GitHub Pages while physical-cube acceptance remains pending. The manual Pages workflow has separate preview-publication and completed-teaching-acceptance inputs; preview publication does not mark teaching acceptance complete. See [deployment runs](https://github.com/Leosteeeve/cube-steps/actions/workflows/pages.yml) for the latest published commit and status.
- cubing.js's lazily loaded 3D/search chunks can exceed Vite's 500 kB warning threshold. They remain separate chunks; loading performance on slow connections has not been benchmarked.
- The pinned cubing.js adapter uses experimental timeline/stickering APIs. Dependency upgrades require the real-renderer and production-worker tests.
- Safari/WebKit keyboard preferences can skip links in ordinary Tab traversal. Tests separately cover focused-link Enter activation and keyboard playback controls.

## Reproduction

```sh
npm ci
npm run typecheck
npm run test:unit
npm run test:corpus
npm run build
npx playwright install chromium webkit
npm run test:e2e
npm run test:production
```

On Windows PowerShell, `npm.cmd` and `npx.cmd` avoid execution-policy restrictions. The Codex Windows sandbox intermittently failed in Vitest's temporary transform cache; the recorded successful runs used the host runtime outside that sandbox.
