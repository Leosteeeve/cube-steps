# CFOP Lab implementation decisions

These decisions were recorded during the approved Native implementation. They supplement the design; they do not establish unmeasured device or human acceptance.

- Ruling: Use the repository-local Git worktree fallback after the native tool returned "Not a git repository" for the outer directory — the approved plan requires isolation and the actual nested repository was verified — cleanup must use Git for this non-managed worktree rather than assume an app attachment.
- Task 4: Ruling: run a width-one complete seed before the width-32 beam. Both evaluate every remaining target and use the same budget; this prevents broad early levels consuming all work before any playable endpoint. Cost if wrong: a weaker initial recommendation, corrected by progressive alternatives. Explicit shortlist-entry-limit RED reproduced and fixed; generator cleanup releases ownership on cancellation. Preparation retains different paths to the same full cube because their final grips may differ.
- Task 6 RED diagnostic: fixed seed 1 seeded only 2/6 colors before 1,975,000 search operations (25,000 reserved for admission), with zero rejected candidates; catalog physical replay passed. Ruling: the width-one seed now evaluates the first feasible formula/preparation in each of four working holds for every remaining pair; the width-32 refinement retains exhaustive bounded preparation/variant enumeration. This is downward tuning inside approved ceilings, not reduced six-color coverage. Cost if wrong: initial ergonomics may be weaker until refinement. Source trace/model/validation remain identical.
- Task 6: Ruling: continue integration with desktop core correctness/performance evidence while explicitly carrying physical-phone, heap-byte and human-handling evidence gaps. No connected representative phone or worker heap API exists. Cost if wrong: device-specific latency/memory or ergonomic issues remain discoverable only in later acceptance; do not label those gates passed. The measured 0.6ms worst batch overshoot is documented; the scheduler checks after bounded steps rather than claiming real-time preemption.
- Task 7: Ruling: split the shared two-million operation ceiling into 1.5 million worker / 500,000 independent client verification operations, and the 25,000 retained-entry ceiling into 24,900 / 100 — both sides must count toward the approved total rather than silently doubling it; the client also bounds duplicate metadata to 64 identities and pending candidates to four — cost if wrong: reduced search coverage on faster devices, reported honestly as a limit. The core's measured 30-second runs used under 0.8 million operations.
- Task 11: Ruling: LabClientSnapshot lacks the settings required by createExperiment(snapshot,...). Add an optional settings snapshot, cloned on valid Analyze; createExperiment requires it — preserves the approved API and exact saved color scope — cost if wrong: a small client API extension to migrate.
- Task 11: Ruling: app version is a fixed Lab data-release identifier (cubesteps-lab-v1), alongside exact search/model/catalog identifiers, because the existing app has no bundled commit identifier — this identifies the schema-producing feature release without inventing a Git hash — cost if wrong: add build revision metadata in a future schema-compatible release.
- Task 13: Ruling: Persist an explicit positive block ordinal and sort by it rather than IndexedDB UUID-key order — required to preserve the approved AB/BA sequence after reload and when appending blocks — cost if wrong: a small pre-release schema field to migrate. Trial history uses timestamp/actual order instead of UUID order.
- Task 14: Ruling: commitLabImport accepts an explicit repository dependency as a third argument — the staged snapshot cannot safely own a live storage handle, and the repository supplies the atomic transaction — cost if wrong: a small internal call signature change.
- Task 14: Ruling: Import-copy remaps experiment/comparison/block/slot/tester/attempt IDs and all graph links, while retaining content-addressed route IDs and formula/action definitions — changing a route ID would invalidate its physical content identity; experiment provenance records its source — cost if wrong: copied experiments intentionally reference the same exact route identity.
- Task 14: Ruling: Saved settings accept a bounded older model version; loading an archive preserves the snapshot and playback badge, while any newly requested analysis uses current-model settings with the same allowed colors — this separates replay from new analysis without silently upgrading archived estimates — cost if wrong: archived settings cannot rerun an unavailable historical search model.
- Task 15: Ruling: Schedule the emergency watchdog at 30.4s rather than at the 30.5s outer target — the actual built UI silent-worker measurement was 30,510ms due to scheduling/render overhead; 100ms headroom preserves the normal 30s search deadline — cost if wrong: an unresponsive worker gets 100ms less grace. Fake-timer regression observed RED-to-GREEN; actual integrated retest follows.
- Task 15: Ruling: Reuse the existing mixed d+2-Lab/Advanced-rejection regression in src/lab/validate.test.ts rather than duplicate it — its exact assertions cover the plan requirement and it runs in the full unit gate — cost if wrong: new trace differences would need another distinct case.
- Final: Ruling: Accept honest delayed elapsed receipts up to the finite safe-number range, rather than reject them above 60s — suspended tabs can deliver a bounded search termination much later, while search work/deadline ceilings remain unchanged — cost if wrong: exported wall-clock elapsed is no longer itself evidence that active search obeyed the deadline; coverage/limits and foreground benchmarks must be interpreted separately. A 99s delayed-stop save regression was observed RED-to-GREEN.
- Final: Ruling: Physical-phone performance/touch evidence remains unverified — publish Experimental with the stated gap and usable Stop/current-route fallback — cost if wrong: device-specific latency or touch issues await real-device acceptance.
- Final: Ruling: Human fingertrick feasibility and benefit remain unverified — retain estimated-handling labels and the empty physical worksheet — cost if wrong: modeled recommendations may feel worse to actual members.
- Final: Ruling: Worker heap-byte bounds remain unverified — retain measured entry counts without presenting them as allocated bytes — cost if wrong: browser-specific memory pressure remains possible.
- Final: Ruling: Global search optimality is not promised — exactness covers the cross reference while route recommendations cover bounded searched candidates — cost if wrong: a better complete route can exist outside the search.
- Final: Ruling: Final suite and deployed revision remain release gates owned by the executor — do not infer completion from the review — cost if wrong: publication must remain withheld until fresh receipts exist.

No minor review findings were deferred.
